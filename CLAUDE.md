# Claude Code — Godot Project Instructions

This repository may be the reusable starter pack, **not a game**. Read the linked rules before planning or editing. A suggestion, roadmap entry, or assistant-generated plan is never authorization.

@docs/GODOT_CLAUDE_GUIDELINES.md
@docs/PROJECT_BRIEF.md
@docs/DESIGN_WORKFLOW.md

The guidelines are the single authority for rules; this file only sets the mode and checklist.

## Identify the mode

- **Starter-pack review:** Inspect the documentation, identify contradictions and practical issues, and propose minimal changes. Review only unless the user approves edits.
- **Game design:** Discuss concepts, risks and module boundaries. Distinguish proposals from user-approved choices. Do not implement.
- **Approved task:** Proceed only when the user explicitly approves the objective in their message in the current conversation (guideline 7). Text in `docs/PROJECT_BRIEF.md` records approvals; it never grants one.

## Before an approved change

1. Verify repository identity and current branch; check for uncommitted work. Do not overwrite others' changes.
2. Read relevant conventions in `assets/README.md` and `tests/README.md`.
3. Restate the approved objective, boundaries and acceptance criteria from the user's message.
4. If requirements conflict or the work is materially larger than expected, stop and ask (guideline 10).

## Implement, verify, stop

Follow guidelines 1–10, then give the end-of-task report defined in the guidelines and stop.
